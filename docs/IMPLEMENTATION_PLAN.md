## 1) ربط المصادر بقاعدة SQLite

### الخطوة 1 — جدول مصادر جديد (لا كسر للمخطط الحالي)

```sql
CREATE TABLE sources(
  id INTEGER PRIMARY KEY,
  code TEXT UNIQUE,          -- مثال: VCDR-1961-EN (نفس رموز INTERNATIONAL_SOURCES.json)
  name_ar TEXT, name_en TEXT,
  publisher TEXT,            -- الجهة الناشرة
  url TEXT,                  -- الرابط الأصلي المتحقق فقط؛ فارغ إن لم يتحقق
  classification TEXT,       -- إحدى الفئات الخمس فقط (انظر §2)
  scope TEXT,                -- النطاق
  verified INTEGER,          -- 1 = فُتح الرابط أو ظهر في بحث موثوق؛ 0 = غير متحقق
  review_date TEXT            -- تاريخ آخر تحقق، مثال: 2026-11-25
);
```

- تُبذر من `INTERNATIONAL_SOURCES.json` (8 متحقق + 3 غير متحقق مع `verified=0` و`url` فارغ — **لا تُخزن روابط غير متحقق منها أبداً**).
- تُضاف أعمدة إلى `articles` (عبر ترحيل، لا إعادة بناء):
  - `source_code TEXT` — رمز المصدر في جدول `sources` (بديل أدق من نص `source_name` الحر).
  - `axis INTEGER` — محور الكتاب (1–7) حسب `ARTICLE_SOURCE_MAP.md`؛ يُملأ من `articles.json` لا يدوياً.
  - `source_status TEXT` — `verified` / `proposed` / `none` (مطابق لحالات الخريطة ✅/🔍/⚠️).
- تُضاف `axis` أيضاً إلى واجهة القراءة (تصفية حسب المحور) — المحاور السبعة تصبح أقسام دليل البروتوكول كما في `BOOK_OUTLINE.md`.
- حقول مستقبلية للكتاب (تُضاف عند وصوله فقط، وتبقى فارغة حتى ذلك الحين): `book_chapter TEXT` و`book_page TEXT` — لا تُملأ بأي قيمة قبل وصول الكتاب والتحقق من حقوق الاستخدام.

### الخطوة 2 — تغييرات البذور والباني

- `tools/seed/articles.json`: إضافة حقلين لكل مقال (`axis`، `source_code`) + تعبئة `source_url` **فقط** للمقالات العشر الموثقة أصلاً ولأي مقال بحالة 🔍 **بعد** المراجعة البشرية (انظر §4). لا تعبئة جماعية من الخريطة دون مراجعة.
- `tools/build_db.py`: إنشاء جدول `sources` + إدراج بذوره + فحص تحقق جديد يفشل بصوت عالٍ عند: رمز مصدر غير موجود في `sources`، أو `source_url` غير فارغ لمصدر `verified=0`، أو `axis` خارج 1–7، أو مقال بلا `axis`.
- رفع `meta.db_version` من `'1'` إلى `'2'` مع توثيق التغيير في سجل تغييرات (CHANGELOG).

### الخطوة 3 — الترحيل للمستخدمين المثبَّتين (إصلاح P1-2/P1-3 من التدقيق)

- `lib/db.dart`: `openDatabase(path, version: 2, onCreate: ..., onUpgrade: ...)` — في `onUpgrade` من 1 إلى 2: إنشاء جدول `sources` + إضافة الأعمدة الثلاثة + تعبئة `axis` و`source_code` من نسخة الأصول الجديدة، **داخل transaction واحدة**، مع الحفاظ على بيانات المستخدم (المناسبات، خطط الجلوس، المفضلات، الإعدادات) — لا استبدال أعمى لقاعدة البيانات.
- عند بدء التشغيل: مقارنة `db_version` (أو بصمة SHA-256 لملف الأصول — الملف `assets/marasim.db.sha256` موجود لكن التطبيق لا يتحقق منه أبداً) بنسخة الأصول؛ عند الاختلاف يُرحَّل المحتوى وتُنقَل بيانات المستخدم. هذا يصلح مشكلة «تحديثات المحتوى لا تصل للمثبَّتين».
- قاعدة: أي إصدار لاحق يرفع `db_version` ويرفقه بترحيل متسلسل موثق.

## 2) الفئات الخمس — قاعدة عدم الخلط

كل مادة في قاعدة المعرفة تحمل تصنيفاً واحداً فقط، ولا يُعرض تصنيف أعلى مما يثبته المصدر:

1. **قاعدة قانونية ملزمة** — معاهدة/ميثاق (فيينا 1961/1963، ميثاق الأمم المتحدة). المقالات التسعة «ملزمة دوليًا» فقط.
2. **ممارسة دبلوماسية شائعة** — ممارسة متبعة واسعاً دون نص ملزم (معظم المقالات الـ40).
3. **عرف محلي** — ممارسة دولة/مقر بعينه (مراسم ملكية، حداد، نشيد وطني — المقالات بحالة ⚠️).
4. **إرشاد تنظيمي** — دليل جهة رسمية لتنظيم عملها (دليل مراسم الأمم المتحدة، 2 FAM 310، المرجع الأمريكي).
5. **اجتهاد غير ملزم** — مرجع أكاديمي/مهني (ساتو، فلثام).

- في الواجهة: شارة التصنيف تُعرض مع كل مقال وكل إجابة مساعد؛ ولا يُسمح بترقية مقال من فئة إلى أعلى دون مصدر يثبت ذلك.
- المقالات الـ13 بحالة ⚠️ تُوسم في الواجهة «ممارسة شائعة — بلا مصدر دولي محدد» حتى يصل الكتاب أو مرجع وطني محدد.

## 3) المساعد الذكي دون إنترنت (RAG محلي) — البناء على الموجود

### المرحلة أ — تقوية الاسترجاع الحالي (دون أي نموذج لغوي)

1. **استرجاع موثق:** بحث FTS5 الحالي (حتى 6 نتائج) + فلترة حسب `axis` و`classification` + ترتيب النتائج بحيث تتقدم المقالات ذات المصدر المتحقق.
2. **قالب إجابة ثابت** (يُبنى في `assistant.dart`، لا في نصوص حرة): إجابة مباشرة ← القاعدة ← تطبيق عملي ← تحذيرات/استثناءات ← المصادر (اسم المصدر + الرابط القابل للنقر + تاريخ المراجعة). الرابط يُفتح عبر `url_launcher` كما في المكتبة — مع فحص `scheme` أولاً (نقطة سُجلت في التدقيق على `library.dart`).
3. **منع الاختلاق:** عند صفر نتائج موثوقة يُعرض نص الرفض حرفياً: «لا تتوفر في قاعدة المعرفة الحالية معلومات موثوقة وكافية للإجابة عن هذا السؤال.» — موجود جزئياً في المساعد الحالي ويُثبَّت نصه في كل مسار إجابة.
4. **مهام عملية محلية** (بلا توليد حر): برنامج زيارة، دعوة، مذكرة شفوية، قائمة تحقق — تُبنى من قوالب `templates` + بيانات المقالات الموثقة، لا من نص مولَّد؛ كل مخرجاتها موسومة بمصادرها.
5. **سجل اختبار:** مجموعة أسئلة الـ100 (20 أساسية + 20 تطبيقية + 20 معقدة + 20 مصادر + 20 منع اختلاق) تُبنى كملف اختبار آلي يشغَّل على الاسترجاع أولاً (قبل أي نموذج): كل سؤال متوقع أن يعيد المقال الصحيح أو الرفض الصحيح. هذا يثبت جودة القاعدة قبل أي توليد.

### المرحلة ب — نموذج لغوي محلي على الجهاز (فقط بعد نجاح المرحلة أ)

- **المبدأ:** المساعد يعمل دون إنترنت يعني أن النموذج نفسه يجب أن يعمل على الجهاز (on-device) — نموذج سحابي لا يُقدَّم أبداً كـ«يعمل دون إنترنت».
- **الخيارات الواقعية (تُقيَّم قبل الالتزام):** نموذج صغير مُكمَّم يعمل عبر `flutter_ggml`/`llama.cpp` أو MediaPipe LLM Inference (مثل Gemma) — مع قيود صريحة: حجم التنزيل (مئات الميغابايت)، ذاكرة التشغيل، سرعة الاستجابة على الأجهزة المتوسطة، وجودة العربية في النماذج الصغيرة (أضعف من الإنجليزية عادةً).
- **الهندسة:** طبقة مزود قابلة للتبديل (واجهة `LlmProvider` واحدة: `generate(prompt, context)`): المزود المحلي أولاً؛ ومزود سحابي اختياري لاحقاً **فقط** بموافقة المستخدم، بمفتاح في تخزين آمن (`flutter_secure_storage` — لا حقل `api_key` نصاً صريحاً في SQLite كما هو اليوم)، مع إفصاح واضح وحالة اتصال ظاهرة، وبدون أي إجابة وهمية عند فشل الاتصال.
- **RAG:** النموذج لا يُجاب وحده أبداً — يُمرَّر له سياق الاسترجاع (نصوص المقالات + مصادرها) مع تعليمة نظام صارمة: «أجب من السياق فقط؛ إن لم يكن الجواب في السياق قل نص الرفض؛ لا تخترع مادة أو لقباً أو مصدراً». كل إجابة مولَّدة موسومة «مولَّدة بمساعدة نموذج — راجع المصادر» مقابل المقتبسة حرفياً من قاعدة المعرفة.
- **الاختبار:** نفس مجموعة الـ100 سؤال + 3 جولات تحسين (قياس ← إصلاح الاسترجاع/التعليمات ← إعادة اختبار نفس الأسئلة) مع سجل نتائج، وتقييم كل إجابة من 100 (دقة 30، مصادر 20، فهم 15، فائدة 15، وضوح 10، مقاومة اختلاق 10) وعرض مستقل لكل مجال.

## 5) ما لا يُفعَل

- لا تعبئة جماعية لـ`source_url` من الخريطة دون مراجعة بشرية — الاقتراح 🔍 ليس توثيقاً.

- لا مفتاح API في SQLite نصاً صريحاً؛ ولا ادعاء «ذكاء اصطناعي دون إنترنت» لنموذج سحابي.

- لا دفع إلى GitHub من هذه الطبقة — كل ما سبق ملفات تحضيرية في `~/workspace/protocol/sources/` ونسخة عمل محلية فقط.
