## الملفات الثنائية — تُولَّد / تُحمَّل وقت البناء (مهم)

هذا المستودع يحوي **ملفات نصية فقط عمدًا**: لا توجد فيه خطوط TTF ولا
قاعدة بيانات SQLite ولا شعار PNG. كل ملف ثنائي يحتاجه البناء يُوفَّر
في GitHub Actions قبل `flutter build`:

| الملف | كيف يتوفر وقت البناء |
|---|---|
| `assets/fonts/*.ttf` (Cairo وAmiri) | تُحمَّل من الإنترنت (خطوط Google) وتُتحقق من صحتها كـTTF؛ فشل التحميل يُفشل البناء صراحةً بدل إنتاج APK بلا خطوط |
| `assets/marasim.db` (+ `.sha256`) | تُبنى من `tools/seed/*.json` عبر `python3 tools/build_db.py tools/seed assets/marasim.db` |
| `assets/logo.png` | يُولَّد محليًا بـPIL من الدالة `fallback_icon` في `tools/make_icon.py` (كرة ذهبية وعمود على خلفية كحلية عميقة، بلا نص) |
| `assets/images/hero*.jpg` | تُحمَّل من Unsplash؛ عند فشل أي تحميل يُولَّد بديل كحلي/ذهبي بـPIL تحت الاسم نفسه |

**نتيجة ذلك للبناء المحلي:** استنساخ هذا المستودع وحده لا يكفي لبناء
التطبيق — يجب أولًا توفير الملفات الأربعة أعلاه (بتشغيل خطوات سير
العمل نفسها) وإلا فشل البناء لأن `pubspec.yaml` يعلنها أصولًا وخطوطًا.
وملف `.gitignore` يمنع التزام هذه الملفات الثنائية مستقبلًا.

## البناء (GitHub Actions — الطريقة المعتمدة)

البناء المحلي بـ Gradle غير ممكن في بيئة التطوير الحالية (Java loopback
محظور) — لذلك يُبنى التطبيق عبر GitHub Actions:

1. أنشئ مستودعًا عامًا باسم `Al-Protocol-Wal-Marasim` على GitHub.
2. ارفع ملفات هذا المشروع عبر موقع GitHub (Upload files) — ارفع مجلد
   `.github/workflows/` **أخيرًا** حتى لا يبدأ البناء قبل اكتمال الرفع.
3. بعد اكتمال الرفع يبدأ البناء تلقائيًا (أو من تبويب Actions →
   Run workflow). مدته المتوقعة 7–8 دقائق.
4. عند النجاح: يُنشأ Release بالوسم `build-<رقم التشغيل>` وفيه ملف
   `Protocol_Ceremonial.apk` — حمّله وثبّته على الهاتف.

**نقاط حرجة في البناء (مثبتة من مشاريع سابقة):**

- `flutter_local_notifications` مثبت على `^22.3.3` — **لا ترفّعه إلى 23.x**؛
  فالإصدار 23 يتطلب compileSdk 37، ومنصة android-37 غير موجودة في
  مستودعات عدّاء Actions ولا يمكن تثبيتها.
- `compileSdk` يبقى على الافتراضي (36)؛ وملف البناء يفعّل
  `isCoreLibraryDesugaringEnabled` + `desugar_jdk_libs 2.1.5`.
- سطر pip في خطوة صور الواجهة يتضمن `pillow` (يحتاجه `make_icon.py`).
- صور الواجهة (8 صور Unsplash) تُحمَّل في CI؛ عند فشل أي تحميل يُولَّد
  بديل كحلي/ذهبي بـ PIL تحت الاسم نفسه حتى لا يتعطل البناء أبدًا.
- الخطوط والشعار وقاعدة البيانات غير ملتزمة في المستودع؛ خطوات CI
  توفرها كلها قبل `flutter build` (انظر جدول «الملفات الثنائية» أعلاه).

## مؤجَّل (ليس في v1.0.1)

- **تصدير DOCX** — التصدير PDF فقط.
- **محتوى دروس الأكاديمية واختباراتها** — الهيكل (3 مستويات، 16 درساً)
  جاهز بعناوين فصول الكتاب، لكن نصوص الدروس والأسئلة قيد الإعداد حتى
  يكتمل استخراج الكتاب ومراجعته؛ لا يُعرض أي محتوى منسوب إلى الكتاب قبله.
- **حفظ محادثات المساعد** — المحادثات الحالية لا تُحفظ بعد انتهاء الجلسة؛
  الحفظ يبدأ مع تطوير المساعد إلى نموذجه اللغوي الكامل.
- **الوضع التوليدي للمساعد (LLM)** — يحتاج مفتاح API وخادمًا؛ الحقل موجود
  في الإعدادات، والمساعد الاسترجاعي يعمل كاملًا بدونه. النموذج غير المتصل
  الحقيقي قيد البناء وفق `docs/CHARTER.md`.
- **بناء iOS** — يحتاج حساب Apple Developer (99$/سنة) + شهادات توقيع
  من مالك الحساب؛ لا يمكن إنجازه من بيئة البناء الحالية وحدها.
- **ترجمة محتوى المقالات والدول إلى الإنجليزية** — الواجهة مترجمة بالكامل،
  أما نصوص المعرفة فتبقى عربية (مع الأسماء الإنجليزية للدول) حتى
  تُراجَع ترجمتها مصدرًا بمصدر.
- **محدوديتان معروفتان في مخطط الجلوس:** إعادة حفظ مخطط معدَّل تتم
  بحذف الصف القديم وإعادة إدخاله (معرّف جديد؛ آمن لأنه لا شيء آخر
  يشير إلى معرّفات المخططات) بدل تحديث مباشر — دالة `updatePlan`
  مخصصة ستكون أنظف. وضيوف الجلوس بلا تاريخ تقديم أوراق اعتماد،
  فيُرتَّب السفراء في المخطط بالاسم فقط لا بالتاريخ.
